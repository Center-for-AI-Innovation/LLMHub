# LLMHub 1.0.0

LLMHub 1.0.0 is out. This release rounds out the platform's cluster story:
jobs can run as the signed-in user, the whole stack runs locally via
Compose, and a Magic Castle deployment path is now first-class.

## User-impersonated job launches

Backend deployments can now submit vec-inf Slurm jobs **as the requesting
cluster user** when impersonation mode is configured, instead of always
running as the service account. GPU-hours land on the user's own
allocation. Direct execution remains supported for deployments that prefer
the service-account model. ([#40](https://github.com/Center-for-AI-Innovation/LLMHub/pull/40))

## Local Docker stack

A Compose file now runs the full app — frontend and backend together — for
local development and demos. ([#54](https://github.com/Center-for-AI-Innovation/LLMHub/pull/54))

## Magic Castle deployment

Terraform configuration and a full deployment guide for standing LLMHub up
on an HPC cluster built with Magic Castle: Slurm controller, login node,
GPU compute nodes, NFS storage, and an optional Caddy reverse proxy for
public access. This is the path used for the NCSA OpenStack (Radiant)
cluster. ([#48](https://github.com/Center-for-AI-Innovation/LLMHub/pull/48))
