# LLMHub 1.1.0

LLMHub 1.1.0 is out. Gated models like Llama now work with your own Hugging
Face token, launching a model that isn't on the cluster yet just works, and
you choose which allocation pays for each launch.

<!-- more -->

## Gated models, with your own token

Models whose publishers require a license, such as Meta's Llama family, now
carry a **Gated** chip in the Model Library. Launching one asks for your
Hugging Face access token. LLMHub uses it to check that you've accepted the
license and to download the weights, and then forgets it: the token isn't
saved, isn't written into the cluster job, and isn't visible to other users.
Every launch is checked against the launching user's own access, so nobody
can launch a gated model on someone else's permission. See
[Gated models](../../getting-started/model-library.md#gated-models).

## No more "launch again in a few minutes"

Launching a model that hasn't been downloaded to the cluster used to fail
with a request to try again later. Now the deployment shows
**Downloading weights** in Your Active Models, and its job starts by itself
when the download finishes. Stopping it while it downloads cancels the
launch.

## Pick the allocation to charge

The launch dialog now lists the Slurm accounts your Delta user belongs to,
so you choose which allocation each launch is charged to. LLMHub preselects
a GPU account when you have one. See
[Launching a model](../../deploying/launching.md).

## Smaller changes

- After signing in you land on the **Model Library** instead of an empty
  chat.
- A deployment's **Chat** button opens the chat with that deployment
  selected, and the chat waits until the model is confirmed before sending,
  so a message can't go to the wrong model.
- Multi-GPU launches no longer fail on Apptainer when an environment
  variable contains a comma.
- Launch requests are checked more strictly on the server, so the model,
  weights and job settings that run are always the ones LLMHub checked.
