# LLMHub 1.1.1: a security fix

LLMHub 1.1.1 fixes a security problem in how models are served. If you
have a model running from before the upgrade, stop it and launch it again.

<!-- more -->

## What was wrong

Each model you launch runs on a compute node as its own vLLM server.
LLMHub checks who you are, whether a deployment is yours or shared with you,
and whether you've accepted a gated model's license, but only for requests
that come through LLMHub. The vLLM servers themselves accepted requests from
anyone on the cluster's network who connected to them directly, without any
of those checks. ([#78](https://github.com/Center-for-AI-Innovation/LLMHub/issues/78))

## What changed

Every deployment's vLLM server now requires its own secret key, which only
LLMHub knows. LLMHub adds it to the requests it forwards for you, and a
request that reaches the server any other way is refused.

Nothing changes in how you use LLMHub. You sign in, chat, share
deployments and call the [API](../../api/index.md) exactly as before, with the
same API key. That key is checked by LLMHub and never passed on to the model
server.

## What you need to do

Models launched **before** the upgrade don't have a key, so they stay open
until they end. To protect one that's still running, click **Stop** in
Your Active Models and launch it again. If you call it from code, the
relaunch gives it a new deployment ID, so copy the new base URL from its
**API** dialog.

## For operators

The release adds a database migration, which the frontend build applies,
and impersonate-mode stacks need their shim environment rebuilt; a normal
deploy of the `v1.1.1` tag does both. See the
[CHANGELOG](https://github.com/Center-for-AI-Innovation/LLMHub/blob/main/CHANGELOG.md#111---2026-10-23)
for details.
